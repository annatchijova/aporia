# Red-team L2 — screenshots

## Alcance

Se revisó el flujo `file picker → base64 → Worker → validación → Gemini inlineData → proposal → confirmación`, preservando los invariantes de L1.

## Ataques considerados

| Amenaza | Control actual | Resultado |
|---|---|---|
| Base64 malformado | regex, `atob`, límite de bytes | rechazado antes de Gemini |
| MIME spoofing | firmas PNG/JPEG/WebP | rechazado |
| Upload sobredimensionado | body 2.1 MB y archivo 1.5 MB | rechazado |
| `Content-Length` ausente o falso | medición del `ArrayBuffer` real | limitado |
| Prompt injection dentro de screenshot | prompt delimita evidencia como datos no confiables | Gemini no es autoridad; requiere confirmación |
| Tipo de artifact desconocido | allowlist explícita | 400 |
| Gemini caído o respuesta inválida | boundary existente y error estructurado | no muta estado |
| Repetición de confirmación | revisión esperada y transición pending | preserva gate L1 |
| XSS en nombre, filename o extracción | React escapa texto; filename no se renderiza como HTML | sin sink HTML observado |

## Mutación observada

Se cambió deliberadamente la firma PNG de `PNG` a `PNX`. El test de artifact falló con `image content does not match its declared type`; la mutación fue revertida.

## Riesgos abiertos

- No se probó todavía un deployment Webflow real con el límite de D1 y Gemini multimodal.
- El artifact binario vive temporalmente en D1; Object Storage es necesario para retención o archivos mayores.
- No hay rate limit por room/participante en este nivel; Gemini ya tiene retry único, pero un atacante puede generar solicitudes repetidas.
- El contenido extraído por Gemini conserva texto proveniente de la imagen y debe seguir tratándose como datos no confiables en niveles posteriores.

## Veredicto

L2 es coherente para screenshots pequeños y conserva la autoridad de L1. No se debe ampliar tamaño ni declarar soporte de retención durable de archivos sin resolver los riesgos abiertos.
